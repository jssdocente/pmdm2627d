# **3.3 Listas y Cuadrículas Eficientes: Lazy Layouts**

Cuando una aplicación necesita mostrar una colección de datos (un catálogo de juegos, una lista de mensajes o un tablero de cartas), el rendimiento del scroll y la gestión de memoria se convierten en el factor más crítico para ofrecer una experiencia fluida a 60 o 120 fotogramas por segundo (fps).

En este apartado analizaremos por qué los contenedores estándar no escalan con grandes conjuntos de datos y dominaremos los contenedores perezosos oficiales de Compose: **`LazyColumn`**, **`LazyRow`** y **`LazyVerticalGrid`**.

---

## 1. El Problema del Rendimiento: `Column` con scroll vs `LazyLayout`

En Compose es muy fácil hacer scroll envolviendo una columna normal con el modificador `verticalScroll`:

```kotlin
// ❌ INEFICIENTE para colecciones medianas o grandes:
Column(modifier = Modifier.verticalScroll(rememberScrollState())) {
    elementos.forEach { item ->
        TarjetaElemento(item)
    }
}
```

### ¿Por qué falla este enfoque con muchos elementos?
- **Instanciación masiva en memoria:** Si la lista contiene 500 elementos, `Column` ejecuta el código de los 500 componibles de golpe, los mide y los coloca en memoria, aunque en la pantalla solo quepan 5 a la vez.
- **Tirones (*Jank*) y consumo de RAM:** Provoca bloqueos en el hilo principal de la interfaz y disparadores constantes del recolector de basura (*Garbage Collector*).

### La Filosofía "Lazy" (Perezosa)
Los componentes **Lazy** implementan el patrón de reciclaje inteligente:
- Solo componen, miden y dibujan los elementos que son **estrictamente visibles** en la ventana gráfica actual (*viewport*), más un pequeño margen de seguridad por arriba y por abajo.
- Conforme el usuario hace scroll, los elementos que salen de la pantalla se descartan y su memoria se reutiliza para los nuevos elementos que entran.

## 2. Listas Verticales con `LazyColumn`

`LazyColumn` es el equivalente moderno y declarativo al antiguo `RecyclerView` de Android, pero sin necesidad de adaptadores (*Adapters*) ni ficheros XML.

### 2.1. Anatomía de `LazyListScope`
Dentro de la lambda de un `LazyColumn` disponemos de métodos especializados para emitir contenido:
- **`item { ... }`:** Permite emitir un único componible (por ejemplo, una cabecera de sección o un banner destacado).
- **`items(coleccion) { item -> ... }`:** Itera sobre una lista o colección de datos emitiendo un componible por cada registro.
- **`itemsIndexed(coleccion) { index, item -> ... }`:** Proporciona además la posición numérica de cada elemento.

```kotlin
@Composable
fun ListaCatalogoJuegos(
    juegos: List<JuegoItem>,
    onJuegoClick: (JuegoItem) -> Unit
) {
    LazyColumn(
        modifier = Modifier.fillMaxSize(),
        contentPadding = PaddingValues(16.dp), // Margen exterior de toda la lista
        verticalArrangement = Arrangement.spacedBy(12.dp) // Hueco automático entre tarjetas
    ) {
        // Cabecera única
        item {
            Text(
                text = "Catálogo de Videojuegos",
                style = MaterialTheme.typography.headlineMedium,
                modifier = Modifier.padding(bottom = 8.dp)
            )
        }

        // Listado dinámico con clave única
        items(
            items = juegos,
            key = { juego -> juego.id } // Optimización crítica de recomposición
        ) { juego ->
            TarjetaJuegoItem(
                juego = juego,
                onClick = { onJuegoClick(juego) }
            )
        }
    }
}
```

## 3. La Clave del Rendimiento: Asignación de `key`

El parámetro `key = { it.id }` en la función `items` es una de las optimizaciones más determinantes en Compose:

- **Sin `key`:** Si el usuario elimina el primer elemento de la lista o aplica un filtro que reordena los registros, Compose identifica cada elemento únicamente por su índice numérico (`0, 1, 2...`). Al cambiar la posición, el compilador se ve forzado a **recomponer cada fila de la lista por completo**.
- **Con `key`:** Al asociar cada fila con el identificador único del modelo de datos (`id`), Compose reconoce instantáneamente qué elemento ha cambiado de sitio, aplicando transiciones suaves y evitando recomposiciones innecesarias en los elementos que no han cambiado.

```kotlin
// Siempre proporciona un identificador único e inmutable como clave
items(
    items = listaTareas,
    key = { tarea -> tarea.id }
) { tarea ->
    FilaTarea(tarea)
}
```

## 4. Cuadrículas Adaptativas con `LazyVerticalGrid`

Cuando el contenido no es puramente secuencial sino que se organiza en filas y columnas (como un catálogo de productos, una galería de fotos o el tablero de cartas de un **Memory Match**), utilizamos **`LazyVerticalGrid`**.

### 4.1. Modos de Cuadrícula
El parámetro `columns` define cómo se distribuyen las celdas:
1. **`GridCells.Fixed(columnas)`:** Fija un número exacto de columnas sin importar el tamaño de la pantalla (ideal para tableros cerrados, como un 4x4).
2. **`GridCells.Adaptive(minSize)`:** Ajusta el número de columnas dinámicamente según el ancho disponible en la pantalla. Si el dispositivo es un teléfono cabrán 2 columnas; si es una tablet o se gira a horizontal, calculará automáticamente 4 o 5 columnas.

### 4.2. Ejemplo: Tablero de Cartas en Cuadrícula

```kotlin
@Composable
fun TableroMemoryGrid(
    cartas: List<CartaItem>,
    onCartaClick: (Int) -> Unit
) {
    LazyVerticalGrid(
        columns = GridCells.Fixed(4), // Tablero de 4 columnas
        modifier = Modifier.fillMaxSize().padding(16.dp),
        horizontalArrangement = Arrangement.spacedBy(8.dp),
        verticalArrangement = Arrangement.spacedBy(8.dp)
    ) {
        items(
            count = cartas.size,
            key = { indice -> cartas[indice].id }
        ) { indice ->
            val carta = cartas[indice]
            TarjetaCartaJuego(
                carta = carta,
                onClick = { onCartaClick(indice) }
            )
        }
    }
}
```

## 5. Diseño de Tarjetas de Colección (`ElevatedCard`)

Para que cada elemento de la lista se distinga visualmente como una superficie táctil independiente, utilizamos las tarjetas de Material 3:

```kotlin
@Composable
fun TarjetaJuegoItem(
    juego: JuegoItem,
    onClick: () -> Unit,
    modifier: Modifier = Modifier
) {
    ElevatedCard(
        onClick = onClick,
        modifier = modifier.fillMaxWidth(),
        shape = MaterialTheme.shapes.medium
    ) {
        Row(
            modifier = Modifier.padding(16.dp),
            verticalAlignment = Alignment.CenterVertically
        ) {
            Surface(
                color = MaterialTheme.colorScheme.primaryContainer,
                shape = MaterialTheme.shapes.small,
                modifier = Modifier.size(48.dp)
            ) {
                Box(contentAlignment = Alignment.Center) {
                    Text(
                        text = juego.titulo.take(1).uppercase(),
                        style = MaterialTheme.typography.titleLarge,
                        color = MaterialTheme.colorScheme.onPrimaryContainer
                    )
                }
            }

            Spacer(modifier = Modifier.width(16.dp))

            Column(modifier = Modifier.weight(1f)) {
                Text(
                    text = juego.titulo,
                    style = MaterialTheme.typography.titleMedium
                )
                Text(
                    text = juego.genero,
                    style = MaterialTheme.typography.bodySmall,
                    color = MaterialTheme.colorScheme.secondary
                )
            }

            Icon(
                imageVector = Icons.Filled.ChevronRight,
                contentDescription = null,
                tint = MaterialTheme.colorScheme.outline
            )
        }
    }
}
```
