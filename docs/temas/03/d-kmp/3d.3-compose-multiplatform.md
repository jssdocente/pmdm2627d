# **3D.3 Compose Multiplatform: interfaz compartida y app de escritorio**

En [3D.2](./3d.2-compartir-logica.md) llevamos la lógica de la app de juegos al código común. Las pantallas, en cambio, seguían en el módulo `androidApp`. En este último apartado de la subunidad las movemos también a `commonMain` con **Compose Multiplatform**, de modo que la **misma interfaz** funcione en Android y en escritorio, y terminamos **empaquetando un instalador** de la app de escritorio.

Al terminar sabrás:

- Qué cambia (y qué no) al pasar de Jetpack Compose a Compose Multiplatform.
- Usar **recursos multiplataforma**: imágenes, iconos y textos traducibles con `Res`.
- Llevar la **navegación con Navigation 3** al código común.
- Adaptar la interfaz a una ventana de escritorio redimensionable.
- Generar el instalador de la app para Windows, macOS o Linux.

---

## 1. Qué cambia y qué no

La buena noticia: **casi todo es igual**. Compose Multiplatform usa los mismos paquetes que Jetpack Compose (`androidx.compose.material3.Text`, `androidx.compose.foundation.layout.Column`…), así que `Column`, `Row`, `Box`, los modificadores, Material 3, `LazyColumn`, `remember` o los estados funcionan exactamente igual que en UT2 y UT3.

Lo que cambia son las piezas que en Android dependen del sistema:

| En Android (Jetpack Compose) | En código común (Compose Multiplatform) |
|---|---|
| `R.drawable.ic_favorite`, `R.string.titulo` | `Res.drawable.ic_favorite`, `Res.string.titulo` |
| `painterResource` y `stringResource` de `androidx.compose.ui.res` | Los mismos nombres, pero de `org.jetbrains.compose.resources` |
| Navigation 3 de AndroidX | Navigation 3 publicada por JetBrains, con una configuración extra de serialización |
| `LocalContext`, `Toast`, `Intent` | No existen: se sustituyen por componentes comunes (por ejemplo, `Snackbar`) o por interfaces por plataforma (3D.2) |
| `enableEdgeToEdge()`, `Activity` | Se quedan en `androidApp` |

## 3. Paso 1: recursos multiplataforma

En Android los recursos están en `res/` y se usan con la clase `R` ([2.3.2](../../02/2.3.2-imagenes-iconos-recursos.md)). En Compose Multiplatform viven en la carpeta **`composeResources`** del código común y se usan con una clase generada llamada **`Res`**:

```text
shared/src/commonMain/composeResources/
├── drawable/              ← imágenes e iconos (PNG, JPG, WebP, SVG y vectores XML de Android)
│   ├── ic_favorite.xml
│   ├── ic_arrow_back.xml
│   └── img_portada.webp
├── values/
│   └── strings.xml        ← textos en el idioma por defecto
├── values-en/
│   └── strings.xml        ← textos en inglés
├── font/                  ← tipografías
└── files/                 ← ficheros que se leen tal cual (JSON, audio…)
```

Las reglas de nombres y los calificadores de idioma son **los mismos que en Android**. Los iconos de Material Symbols que descargaste en formato XML para Android ([2.3.2](../../02/2.3.2-imagenes-iconos-recursos.md#de-donde-sacar-los-iconos-material-symbols)) se copian sin cambios en `drawable/`.

Al **compilar** el proyecto, se genera la clase `Res` con un acceso para cada recurso:

```kotlin
import misjuegos.shared.generated.resources.Res
import misjuegos.shared.generated.resources.ic_favorite
import misjuegos.shared.generated.resources.titulo_app
import org.jetbrains.compose.resources.painterResource
import org.jetbrains.compose.resources.stringResource

@Composable
fun Cabecera() {
    Row(verticalAlignment = Alignment.CenterVertically) {
        Icon(painterResource(Res.drawable.ic_favorite), contentDescription = null)
        Text(stringResource(Res.string.titulo_app))
    }
}
```

| Android | Compose Multiplatform |
|---|---|
| `res/drawable/logo.xml` | `composeResources/drawable/logo.xml` |
| `res/values/strings.xml` | `composeResources/values/strings.xml` |
| `painterResource(R.drawable.logo)` | `painterResource(Res.drawable.logo)` |
| `stringResource(R.string.saludo, "Ana")` | `stringResource(Res.string.saludo, "Ana")` |
| `import com.dam.app.R` | `import misjuegos.shared.generated.resources.Res` (y un `import` por recurso) |

- El paquete de `Res` es, por defecto, `{nombre del proyecto}.{módulo}.generated.resources`. El IDE lo importa solo si usas el autocompletado.
- Si añades un recurso y `Res.drawable.…` sale en rojo, **compila el proyecto** (**Build → Build Project**) para que se regenere la clase.

!!! note "El icono de la app no va en `composeResources`"
    El icono del lanzador de Android sigue en `androidApp/src/main/res/mipmap-…` ([Anexo A](../../00-android/anexos/a-iconos-app-recursos.md)), y el de la app de escritorio se configura al empaquetar (apartado 8). `composeResources` es para los recursos que usa la **interfaz**.

## 4. Paso 2: las pantallas al código común

Mueve los ficheros de las pantallas (`PantallaCatalogo.kt`, `PantallaDetalle.kt` y sus componentes) desde `androidApp` a `shared/src/commonMain`, junto a sus ViewModel. Después:

1. **Cambia los recursos:** `R.drawable.x` → `Res.drawable.x` y `R.string.x` → `Res.string.x`, y sustituye los imports de `androidx.compose.ui.res` por los de `org.jetbrains.compose.resources`.

2. **Elimina lo que solo existe en Android:** si una pantalla usaba `LocalContext` para mostrar un `Toast`, cámbialo por un `Snackbar` de Material 3; si lanzaba un `Intent`, usa una interfaz por plataforma como el `Compartidor` de 3D.2.

3. **Compila** y corrige lo que quede en rojo. Normalmente son solo imports.

```kotlin
// shared/src/commonMain/kotlin/com/dam/misjuegos/juegos/ui/detalle/PantallaDetalle.kt
@OptIn(ExperimentalMaterial3Api::class)
@Composable

    Scaffold(
        modifier = modifier,
        topBar = {
            TopAppBar(
                title = { Text(estado.juego?.titulo ?: stringResource(Res.string.juego_no_encontrado)) },
                navigationIcon = {
                    IconButton(onClick = onVolver) {
                        Icon(painterResource(Res.drawable.ic_arrow_back), contentDescription = stringResource(Res.string.volver))
                    }
                },
                actions = {
                    IconButton(onClick = onCompartirClick) {
                        Icon(painterResource(Res.drawable.ic_share), contentDescription = stringResource(Res.string.compartir))
                    }
                    IconButton(onClick = onFavoritoClick) {

                                if (estado.juego?.esFavorito == true) Res.drawable.ic_favorite_filled

                                else Res.string.anadir_favorito

                    }
                }
            )
        }
    ) { innerPadding ->
        // … igual que en 3C …
    }

```

Fíjate en que la pantalla es **idéntica** a la de Android salvo por `Res`. Todo lo que aprendiste sobre maquetación, Material 3 y estado sigue valiendo.

## 5. Paso 3: la navegación en el código común

La navegación de 3B.1 y 3C.3 también se mueve a `commonMain`. Hay **una diferencia importante** con Android: la configuración de serialización de la pila.

### 5.1. Por qué hace falta `SavedStateConfiguration`

En [3B.1](../b-navegacion/3b.1-navigation3.md#4-paso-2-crear-la-pila) vimos que `rememberNavBackStack` guarda la pila convirtiendo cada clave a texto. En Android lo hace usando **reflexión**: descubre por sí solo qué clases de clave existen. Esa técnica no está disponible en todas las plataformas (iOS y web no la tienen), así que en el código común hay que **registrar explícitamente** todas las claves de navegación:

```kotlin
// shared/src/commonMain/kotlin/com/dam/misjuegos/navegacion/Rutas.kt
@Serializable data object Catalogo : NavKey
@Serializable data class Detalle(val juegoId: Int) : NavKey

/** Todas las claves de navegación de la app, para poder guardar la pila en cualquier plataforma. */
val configuracionNavegacion = SavedStateConfiguration {
    serializersModule = SerializersModule {
        polymorphic(NavKey::class) {
            subclass(Catalogo::class, Catalogo.serializer())
            subclass(Detalle::class, Detalle.serializer())
        }
    }
}
```

Es imprescindible para iOS y web. En Android y escritorio, que usan la JVM, funcionaría sin ella, pero como este código es **común**, la usamos siempre: así la app está lista para cualquier plataforma.

!!! warning "Cada clave nueva, registrada"
    Cuando añadas una pantalla, añade también su clave al `polymorphic { … }`. Si se te olvida, la app compilará, pero fallará en iOS o web al intentar guardar la pila con esa pantalla abierta.

### 5.2. La navegación común

```kotlin
// shared/src/commonMain/kotlin/com/dam/misjuegos/navegacion/AppNavegacion.kt
@Composable
fun AppNavegacion() {
    val pila = rememberNavBackStack(configuracionNavegacion, Catalogo)

    NavDisplay(
        backStack = pila,
        onBack = { pila.removeLastOrNull() },
        entryDecorators = listOf(
            rememberSaveableStateHolderNavEntryDecorator(),
            rememberViewModelStoreNavEntryDecorator()
        ),
        entryProvider = entryProvider {
            entry<Catalogo> {
                val viewModel = koinViewModel<CatalogoViewModel>()
                val estado by viewModel.uiState.collectAsStateWithLifecycle()
                PantallaCatalogo(
                    estado = estado,
                    onJuegoClick = { id -> pila.add(Detalle(id)) },
                    onFavoritoClick = viewModel::onFavoritoClick,
                    onFiltroCambiado = viewModel::onFiltroCambiado
                )
            }
            entry<Detalle> { clave ->
                val viewModel = koinViewModel<DetalleViewModel> { parametersOf(clave.juegoId) }
                val estado by viewModel.uiState.collectAsStateWithLifecycle()
                PantallaDetalle(
                    estado = estado,
                    onFavoritoClick = viewModel::onFavoritoClick,
                    onCompartirClick = viewModel::onCompartirClick,
                    onVolver = { pila.removeLastOrNull() }
                )
            }
        }
    )
}

// shared/src/commonMain/kotlin/com/dam/misjuegos/App.kt
@Composable
fun App() {
    MisJuegosTheme {
        AppNavegacion()
    }
}
```

Es el mismo código de 3C.3. Los únicos cambios son el primer parámetro de `rememberNavBackStack` y que ahora vive en `commonMain`.

!!! info "El botón atrás en escritorio"
    En escritorio no hay botón ni gesto «atrás» del sistema, así que la **flecha de la barra superior** es la forma de volver. Por eso nuestras pantallas siempre la incluyen (`onVolver`). En Android siguen funcionando también el botón y el gesto del sistema mediante `onBack`.

## 7. Una interfaz para ventanas de cualquier tamaño

En escritorio, el usuario **redimensiona la ventana** continuamente: puede ser estrecha como un móvil o ocupar todo un monitor. Es exactamente el problema que resolvimos en [3B.2 Diseño adaptativo](../b-navegacion/3b.2-diseno-adaptativo.md), y las mismas ideas funcionan aquí.

Para adaptaciones sencillas, `BoxWithConstraints` (de Compose, estable en todas las plataformas) permite conocer el espacio disponible y decidir:

```kotlin
@Composable
fun ListaOCuadricula(juegos: List<Juego>, onJuegoClick: (Int) -> Unit) {
    BoxWithConstraints {
        if (maxWidth >= 600.dp) {
            LazyVerticalGrid(columns = GridCells.Adaptive(220.dp)) {
                items(juegos, key = { it.id }) { TarjetaJuego(it, onJuegoClick) }
            }
        } else {
            LazyColumn {
                items(juegos, key = { it.id }) { FilaJuego(it, onJuegoClick) }
            }
        }
    }
}
```

`GridCells.Adaptive` y `Modifier.widthIn(max = …)` también funcionan igual que en Android. Las librerías de Material 3 adaptativo de 3B.2 (`currentWindowAdaptiveInfo`, `NavigationSuiteScaffold`, lista-detalle con escenas) tienen versión multiplataforma publicada por JetBrains, aunque en el momento de escribir estos apuntes está en beta o alpha.

!!! tip "Diseña en escritorio con Hot Reload"
    Con la app de escritorio abierta y Compose Hot Reload activo (3D.1), redimensiona la ventana mientras cambias el código: verás al instante cómo responde el diseño a cada ancho. Es la forma más rápida de probar un diseño adaptativo.

### Vistas previas en código común

La anotación `@Preview` funciona también en `commonMain` (librería `ui-tooling-preview` de Compose Multiplatform, incluida desde 3D.1). Las técnicas de [Diseño con @Preview y datos mock](../../00-android/00-compose/26-preview-diseno-mock.md) siguen valiendo.

## 8. Empaquetar la app de escritorio

Para distribuir la app hay que generar un **instalador nativo** para cada sistema operativo. El plugin de Compose lo hace con `jpackage`, una herramienta del JDK, a partir del bloque `nativeDistributions` que vimos en 3D.1:

```kotlin
// desktopApp/build.gradle.kts
compose.desktop {
    application {
        mainClass = "com.dam.misjuegos.MainKt"

        nativeDistributions {
            targetFormats(TargetFormat.Msi, TargetFormat.Dmg, TargetFormat.Deb)
            packageName = "MisJuegos"
            packageVersion = "1.0.0"
            description = "Gestor de biblioteca de videojuegos"
            vendor = "IES Albarregas"

            windows { iconFile.set(project.file("icons/icono.ico")) }
            macOS { iconFile.set(project.file("icons/icono.icns")) }
            linux { iconFile.set(project.file("icons/icono.png")) }
        }
    }
}
```

### Tareas de Gradle

| Tarea | Qué hace |
|---|---|
| `./gradlew :desktopApp:run` | Ejecuta la app sin empaquetar (la forma rápida de desarrollo) |
| `./gradlew :desktopApp:createDistributable` | Crea la app con su propio Java incluido, sin instalador |
| `./gradlew :desktopApp:runDistributable` | Ejecuta esa versión empaquetada, para probarla antes de distribuirla |
| `./gradlew :desktopApp:packageDistributionForCurrentOS` | Genera el **instalador** del sistema operativo en el que estás |
| `./gradlew :desktopApp:packageMsi` (o `packageDmg`, `packageDeb`…) | Genera un formato concreto |

Los ficheros generados aparecen en `desktopApp/build/compose/binaries/`.

| Sistema operativo | Formatos |
|---|---|
| Windows | `.msi`, `.exe` |
| macOS | `.dmg`, `.pkg` |
| Linux | `.deb`, `.rpm` |

!!! warning "Cada instalador, en su sistema operativo"
    No se puede generar un instalador para otro sistema: el `.msi` solo se genera en Windows, el `.dmg` solo en macOS y el `.deb` solo en Linux. Las tareas que no corresponden a tu sistema se omiten. Para generar los tres, hace falta un ordenador (o un servicio de integración continua) de cada sistema.

!!! note "Requisitos y versiones"
    - `jpackage` necesita un **JDK 17 o superior** (no basta con un JRE).
    - El formato de `packageVersion` depende del instalador: para `.msi` y `.exe` debe ser `MAYOR.MENOR.BUILD`, con `MAYOR` y `MENOR` de 255 como máximo. Una versión como `1.0.0` es válida en todos.
    - Los iconos deben estar en el formato de cada sistema: `.ico` (Windows), `.icns` (macOS) y `.png` (Linux).

La app de Android se prepara para Google Play de otra forma, con firma y Android App Bundle: lo veremos en la subunidad **3E**.

## 9. Errores frecuentes

!!! warning "`Res` o `Res.drawable.…` en rojo"
    La clase `Res` se genera al compilar. Compila el proyecto y comprueba que el recurso está en `shared/src/commonMain/composeResources/…` con un nombre válido.

!!! warning "Sigo usando `R.drawable` en `commonMain`"
    `R` solo existe en Android. En el código común, todos los recursos van con `Res` y las funciones de `org.jetbrains.compose.resources`.

!!! warning "`painterResource` no acepta `Res.drawable…`"
    Has importado `androidx.compose.ui.res.painterResource` (la de Android). Usa `org.jetbrains.compose.resources.painterResource`.

!!! warning "La app falla en iOS o web al guardar la pila de navegación"
    Falta registrar una clave en `configuracionNavegacion` (apartado 5.1), o se creó la pila con `rememberNavBackStack(Catalogo)` sin la configuración.

!!! warning "`LocalContext` o `Toast` no se encuentran"
    Son de Android. Usa un `Snackbar` para los mensajes y una interfaz por plataforma (3D.2) para todo lo que necesite el `Context`.

!!! warning "`packageMsi` no hace nada"
    Estás en macOS o Linux: esa tarea se omite. Ejecuta `packageDistributionForCurrentOS` para generar el formato de tu sistema.

!!! warning "Error de empaquetado: no encuentra `jpackage`"
    Gradle está usando un JRE o un JDK anterior al 17. Configura un JDK 17 o superior en `JAVA_HOME` o en el **Gradle JVM** del IDE.

## 10. Retos

Parte de la app de 3D.2 con las pantallas ya en `commonMain`.

### 🟢 Básico: textos traducibles en las dos apps

Mueve todos los textos de las pantallas a `composeResources/values/strings.xml` y crea su traducción en `values-en/strings.xml`. Comprueba que, al poner el sistema en inglés, cambian tanto la app Android como la de escritorio.

??? success "Solución"

    ```xml
    <!-- shared/src/commonMain/composeResources/values/strings.xml -->
    <resources>
        <string name="titulo_app">Mis juegos</string>
        <string name="juego_no_encontrado">Juego no encontrado</string>
        <string name="volver">Volver</string>
        <string name="compartir">Compartir</string>
        <string name="anadir_favorito">Añadir a favoritos</string>
        <string name="quitar_favorito">Quitar de favoritos</string>
        <string name="plataforma">Plataforma: %1$s</string>
    </resources>

    <!-- shared/src/commonMain/composeResources/values-en/strings.xml -->
    <resources>
        <string name="titulo_app">My games</string>
        <string name="juego_no_encontrado">Game not found</string>
        <string name="volver">Back</string>
        <string name="compartir">Share</string>
        <string name="anadir_favorito">Add to favourites</string>
        <string name="quitar_favorito">Remove from favourites</string>
        <string name="plataforma">Platform: %1$s</string>
    </resources>
    ```

    ```kotlin
    Text(stringResource(Res.string.plataforma, juego.plataforma))
    ```

    Claves de la solución:

    - Es el mismo formato de `strings.xml` que en Android, con los mismos calificadores de idioma y los mismos marcadores (`%1$s`).
    - La app de escritorio toma el idioma del **sistema operativo**; la de Android, el del móvil.
    - Recuerda compilar tras añadir textos para que aparezcan en `Res.string`.
    - Los textos de accesibilidad (`contentDescription`) también se traducen: TalkBack los leerá en el idioma del usuario.

### 🟡 Intermedio: pantalla de ajustes común

Añade una pantalla `Ajustes` accesible desde un icono de la barra superior del catálogo, con un interruptor «Mostrar solo favoritos» que filtre el catálogo. Registra la nueva clave de navegación donde corresponda y comprueba que funciona en las dos apps.

??? success "Solución"

    La preferencia se guarda **en el dominio**, igual que el favorito en 3C.2, para que la lean tanto el catálogo como los ajustes:

    ```kotlin
    // Rutas.kt
    @Serializable data object Ajustes : NavKey

    val configuracionNavegacion = SavedStateConfiguration {
        serializersModule = SerializersModule {
            polymorphic(NavKey::class) {
                subclass(Catalogo::class, Catalogo.serializer())
                subclass(Detalle::class, Detalle.serializer())
                subclass(Ajustes::class, Ajustes.serializer())      // ← nueva clave registrada
            }
        }
    }

    // domain
    interface PreferenciasRepositorio {
        val soloFavoritos: StateFlow<Boolean>
        fun cambiarSoloFavoritos(valor: Boolean)
    }

    // data (en memoria; en UT4 será DataStore)
    class PreferenciasEnMemoria : PreferenciasRepositorio {
        private val _soloFavoritos = MutableStateFlow(false)
        override val soloFavoritos = _soloFavoritos.asStateFlow()
        override fun cambiarSoloFavoritos(valor: Boolean) { _soloFavoritos.value = valor }
    }

    // AjustesViewModel (commonMain)
    class AjustesViewModel(private val preferencias: PreferenciasRepositorio) : ViewModel() {
        val soloFavoritos = preferencias.soloFavoritos
        fun onSoloFavoritosCambiado(valor: Boolean) = preferencias.cambiarSoloFavoritos(valor)
    }

    // CatalogoViewModel: combina también la preferencia
    combine(obtenerJuegos(), filtro, preferencias.soloFavoritos) { juegos, plataforma, soloFav -> /* … */ }

    // Koin
    singleOf(::PreferenciasEnMemoria) bind PreferenciasRepositorio::class
    viewModelOf(::AjustesViewModel)

    // AppNavegacion.kt
    entry<Catalogo> {
        // … como en el apartado 5.2, añadiendo:
        // onAjustesClick = { pila.add(Ajustes) }
    }
    entry<Ajustes> {
        val viewModel = koinViewModel<AjustesViewModel>()
        val soloFavoritos by viewModel.soloFavoritos.collectAsStateWithLifecycle()
        PantallaAjustes(
            soloFavoritos = soloFavoritos,
            onSoloFavoritosCambiado = viewModel::onSoloFavoritosCambiado,
            onVolver = { pila.removeLastOrNull() }
        )
    }
    ```

    Claves de la solución:

    - **Nueva pantalla = nueva clave registrada** en `configuracionNavegacion`. Es el paso que más se olvida.
    - Cada pantalla tiene su propio ViewModel, y los dos leen la preferencia del mismo **repositorio** (única fuente de verdad). Es más limpio que intentar compartir un ViewModel entre pantallas.
    - El repositorio de preferencias en memoria se sustituirá en UT4 por **DataStore**, que también es multiplataforma, sin tocar los ViewModel.
    - Todo el código está en `commonMain`: la pantalla aparece en Android y en escritorio sin escribir nada específico.

### 🔴 Avanzado: instalador de la app de escritorio

Prepara la app de escritorio para distribuirla:

- La ventana se abre con 1000 × 700 dp, con un tamaño mínimo de 400 × 500 píxeles y el título «Mis juegos».
- El catálogo muestra una lista si la ventana mide menos de 600 dp de ancho y una cuadrícula en caso contrario.
- Genera el instalador de tu sistema operativo con nombre, versión `1.0.0`, descripción e icono propios, e instálalo como cualquier otra aplicación.

??? success "Solución"

    Para que `desktopApp` pueda usar un recurso de `shared` (el logotipo de la ventana), la clase `Res` debe ser pública; por defecto es `internal`:

    ```kotlin
    // shared/build.gradle.kts
    compose.resources {
        publicResClass = true
    }
    ```

    ```kotlin
    // desktopApp/src/main/kotlin/com/dam/misjuegos/main.kt
    fun main() {
        initKoin()
        application {
            Window(
                onCloseRequest = ::exitApplication,
                title = "Mis juegos",
                icon = painterResource(Res.drawable.ic_logo),          // icono de la ventana y la barra de tareas
                state = rememberWindowState(width = 1000.dp, height = 700.dp)
            ) {
                window.minimumSize = java.awt.Dimension(400, 500)
                App()
            }
        }
    }
    ```

    ```kotlin
    // shared/src/commonMain/…/PantallaCatalogo.kt (fragmento del estado Exito)
    is CatalogoUiState.Exito -> ListaOCuadricula(
        juegos = estado.juegos,
        onJuegoClick = onJuegoClick
    )
    ```

    ```kotlin
    // desktopApp/build.gradle.kts
    compose.desktop {
        application {
            mainClass = "com.dam.misjuegos.MainKt"
            nativeDistributions {
                targetFormats(TargetFormat.Msi, TargetFormat.Dmg, TargetFormat.Deb)
                packageName = "MisJuegos"
                packageVersion = "1.0.0"
                description = "Gestor de biblioteca de videojuegos"
                vendor = "IES Albarregas"
                windows {
                    iconFile.set(project.file("icons/icono.ico"))
                    menuGroup = "Mis juegos"         // carpeta del menú Inicio
                    shortcut = true                  // acceso directo en el escritorio
                }
                macOS { iconFile.set(project.file("icons/icono.icns")) }
                linux { iconFile.set(project.file("icons/icono.png")) }
            }
        }
    }
    ```

    ```bash
    ./gradlew :desktopApp:packageDistributionForCurrentOS
    ```

    Claves de la solución:

    - El **icono de la ventana** (parámetro `icon` de `Window`) y el **icono del instalador** (`iconFile`) son cosas distintas: el primero se ve en la barra de título y en la barra de tareas mientras la app está abierta; el segundo, en el acceso directo y en el sistema.
    - El tamaño mínimo evita que el usuario reduzca la ventana tanto que la interfaz deje de caber.
    - `ListaOCuadricula` (apartado 7) está en el código común, así que también se adapta en tablets Android.
    - Antes de distribuir, prueba la versión empaquetada con `runDistributable`: incluye su propio Java y es la que recibirá el usuario.
    - El instalador aparece en `desktopApp/build/compose/binaries/main/`, en la subcarpeta del formato (`msi`, `dmg` o `deb`).
