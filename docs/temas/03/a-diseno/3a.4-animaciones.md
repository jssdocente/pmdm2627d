# **3A.4 Animaciones que siguen al estado**

En Compose, una animación **no guarda nada**. Se calcula a partir del estado: si el estado dice que un elemento es favorito, está desplegado o es visible, la animación lleva el dibujo hasta ahí. Si el estado cambia a medio camino, la animación cambia de destino sin saltos.

Es la misma idea de siempre, `UI = f(estado)`, con una diferencia: entre dos estados, Compose dibuja también los pasos intermedios.

<figure class="arq-fig">
--8<-- "docs/temas/03/a-diseno/images/an-sigue-estado.svg"
<figcaption>El estado decide el destino y la animación calcula cómo llegar. El dato solo vive en el estado.</figcaption>
</figure>

!!! warning "La animación no es el estado"
    Si para saber si una tarjeta está desplegada tienes que preguntarle a su animación, el diseño está mal. El dato va en el estado (`remember` o `UiState`); la animación solo lo lee.

---

## 1. Animar un valor: `animate*AsState`

Es la herramienta que más vas a usar. Le das el valor de **destino** y te devuelve un `State` con el valor de **cada fotograma**. Hay una función por tipo: `animateFloatAsState`, `animateDpAsState`, `animateColorAsState`, `animateIntAsState`…

```kotlin
@Composable
fun BotonFavorito(esFavorito: Boolean, onClick: () -> Unit) {
    // Cuando cambia esFavorito, escala y color recorren los valores intermedios
    val escala by animateFloatAsState(
        targetValue = if (esFavorito) 1.25f else 1f,
        label = "escalaFavorito"
    )
    val color by animateColorAsState(
        targetValue = if (esFavorito) MaterialTheme.colorScheme.error
        else MaterialTheme.colorScheme.onSurfaceVariant,
        label = "colorFavorito"
    )

    IconToggleButton(checked = esFavorito, onCheckedChange = { onClick() }) {
        Icon(
            painter = painterResource(R.drawable.ic_favorite),
            contentDescription = null,
            tint = color,
            modifier = Modifier.graphicsLayer {
                scaleX = escala
                scaleY = escala
            }
        )
    }
}
```

- `by` es necesario: sin él tendrías un `State<Float>`, no un `Float`.
- `label` no cambia nada en la app: identifica la animación en las herramientas del IDE.

### 1.1. Elegir cómo se mueve: `animationSpec`

| Especificación | Cómo se mueve | Cuándo usarla |
| :--- | :--- | :--- |
| `spring()` (por defecto) | Como un muelle; puede rebotar | Respuesta a un toque. Si cambia a medias, sigue con naturalidad |
| `tween(durationMillis = 300)` | En un tiempo exacto, con una curva | Fundidos y movimientos de duración conocida |
| `tween(1_000, easing = LinearEasing)` | A velocidad constante | Un progreso que avanza con el tiempo |

```kotlin
val escala by animateFloatAsState(
    targetValue = if (esFavorito) 1.25f else 1f,
    animationSpec = spring(dampingRatio = Spring.DampingRatioMediumBouncy),
    label = "escalaFavorito"
)
```

## 2. Transformar el dibujo: `graphicsLayer`

`Modifier.graphicsLayer` aplica una transformación al dibujo ya hecho, **sin volver a medir ni a colocar** el elemento: los vecinos no se mueven y resulta muy eficiente, justo lo que interesa en una animación.

| Propiedad | Qué hace |
| :--- | :--- |
| `scaleX`, `scaleY` | Escala (1f es el tamaño normal) |
| `alpha` | Opacidad, de 0f a 1f |
| `rotationZ` | Giro en el plano de la pantalla, en grados |
| `translationX`, `translationY` | Desplazamiento, en píxeles |

Hay más propiedades, entre ellas giros en los otros ejes: consulta los [modificadores gráficos](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers?hl=es-419) y la [referencia de `GraphicsLayerScope`](https://developer.android.com/reference/kotlin/androidx/compose/ui/graphics/GraphicsLayerScope).

!!! tip "La forma con lambda"
    `graphicsLayer { scaleX = escala }` lee el valor animado **al dibujar**, no al componer. Así, cada fotograma no recompone la pantalla: solo se vuelve a dibujar esa capa.

## 3. Animar el contenido

| Herramienta | Para qué | Dónde lo has visto |
| :--- | :--- | :--- |
| `Modifier.animateContentSize()` | Un elemento que cambia de tamaño crece y encoge con suavidad | [Codelab 3.02](../codelabs/02-catalogo-lazycolumn.md#4-paso-2-la-tarjeta-de-un-curso) |

| `AnimatedVisibility(visible = …)` | Un elemento aparece y desaparece | — |
| `AnimatedContent(targetState = …)` | Cambio de contenido con una transición a tu medida | — |

```kotlin
AnimatedVisibility(visible = desplegado) {
    Text("Se ve solo si desplegado es true, y entra y sale con una animación")
}
```

Las transiciones **entre pantallas** se configuran en `NavDisplay`: [3B.1 §11](../b-navegacion/3b.1-navigation3.md#11-animaciones-de-transicion).

## 4. Errores frecuentes

| Síntoma | Causa | Solución |
| :--- | :--- | :--- |
| La animación no arranca | El `targetValue` no cambia: es una constante o no depende del estado | Calcula el destino a partir del estado |
| Al girar el móvil se pierde lo que se veía | El dato estaba en la animación o en una variable sin guardar | Guarda el dato en `rememberSaveable` o en el `UiState`; la animación lo recupera sola |
| Los elementos vecinos se mueven al animar | Se anima el tamaño con `size` u `offset` en medio del diseño | Usa `graphicsLayer` si solo quieres cambiar el dibujo |
| Una tarea espera a que termine la animación | La lógica depende de la animación | Las esperas son lógica: van en el ViewModel, con `delay` ([3C.1 §5](../c-arquitectura/3c.1-capa-ui-viewmodel.md#5-tareas-con-tiempo-en-el-viewmodel)) |

## 5. Retos

### 🟢 Básico

Añade a una tarjeta un icono de flecha que gire 180° con `rotationZ` al desplegarla. El dato «desplegada» va en un `rememberSaveable`.

### 🟡 Intermedio

Haz que el contador de partidas de una ficha crezca un instante al sumar una: usa `animateFloatAsState` y comprueba que no se mueve el botón de al lado.

### 🔴 Avanzado

Crea un `AnimatedContent` que muestre un número y haga entrar el valor nuevo desde abajo al aumentar y desde arriba al disminuir. Lee en la documentación cómo usar `transitionSpec`.
