# Operador When

Piensa en el operador `when` como el `switch` de Java que fue al gimnasio, leyó varios libros de filosofía y se volvió increíblemente flexible y poderoso.

Vamos a desglosar todos sus usos, desde el reemplazo directo del `switch` hasta sus capacidades más expresivas, comparándolo siempre cara a cara con su equivalente en Java.

---

### 1. El Caso Básico: `when` como un `switch` Mejorado

Este es el uso más directo y fácil de entender. Se parece mucho a un `switch-case` de Java, pero con mejoras clave en seguridad y legibilidad:

-   `case X:` se convierte en `X ->`.
-   `default:` se convierte en `else ->`.
-   **No necesitas `break;`**. ¡Esto elimina toda una categoría de bugs! La ejecución se detiene automáticamente al encontrar la primera rama que coincide.

=== "Java (switch clásico)"
    ```java
    int day = 2;
    String dayName;
    switch (day) {
        case 1:
            dayName = "Lunes";
            break;
        case 2:
            dayName = "Martes";
            break;
        case 3:
            dayName = "Miércoles";
            break;
        default:
            dayName = "Otro día";
            break;
    }
    System.out.println(dayName); // Martes
    ```

=== "Kotlin (when básico)"
    ```kotlin
    val day = 2
    val dayName = when (day) {
        1 -> "Lunes"
        2 -> "Martes"
        3 -> "Miércoles"
        else -> "Otro día"
    }
    println(dayName) // Martes
    ```

**Ventajas inmediatas en Kotlin:**

-   Más limpio y conciso.
-   A prueba de errores de *fall-through* (olvidar un `break;`).
-   **Puede ser una expresión:** Asignamos el resultado del `when` directamente a la variable `dayName`.

### 2. `when` como Expresión (Su primer superpoder)

Cuando usas `when` para devolver un valor (como en el ejemplo anterior), el compilador de Kotlin te exige que seas **exhaustivo**. Esto significa que *debes* cubrir todos los casos posibles.

Esto resulta extraordinariamente potente con tipos enumerados (`enum`) o jerarquías selladas (`sealed classes`).

=== "Java (switch con enum)"
    ```java
    public enum DayOfWeek {
        MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
    }

    public String getDayType(DayOfWeek day) {
        // En Java tradicional el switch no devuelve directamente una expresión:
        // Debemos usar return en cada caso o asignar a una variable auxiliar
        switch (day) {
            case MONDAY:
            case TUESDAY:
            case WEDNESDAY:
            case THURSDAY:
            case FRIDAY:
                return "Día laboral";
            case SATURDAY:
            case SUNDAY:
                return "Fin de semana";
            default:
                // Aunque cubramos todos los valores del enum, Java suele exigir default o excepción
                throw new IllegalArgumentException("Día no válido: " + day);
        }
    }
    ```

=== "Kotlin (when como expresión)"
    ```kotlin
    enum class DayOfWeek {
        MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
    }

    fun getDayType(day: DayOfWeek): String {
        return when (day) {
            DayOfWeek.MONDAY, DayOfWeek.TUESDAY, DayOfWeek.WEDNESDAY, DayOfWeek.THURSDAY, DayOfWeek.FRIDAY -> "Día laboral"
            DayOfWeek.SATURDAY, DayOfWeek.SUNDAY -> "Fin de semana"
            // No se necesita 'else' aquí. ¿Por qué?
            // Porque hemos cubierto TODOS los valores posibles del enum.
            // Si añadieras un nuevo día al enum, ¡este código fallará en compilación
            // hasta que lo manejes! Esto es seguridad en tiempo de compilación.
        }
    }
    ```

**Nuevas características mostradas:**

-   **Combinar casos:** Puedes colocar varias condiciones en la misma rama separadas por comas (`,`), evitando la cascada de `case` repetidos de Java.
-   **Exhaustividad garantizada:** El compilador te protege de olvidar casos futuros sin necesidad de lanzar excepciones en tiempo de ejecución.

### 3. `when` sin Argumento (El modo "if-else if" inteligente)

Aquí es donde `when` supera ampliamente al `switch` de Java. Puedes utilizar `when` sin pasarle ningún objeto entre paréntesis. Cuando lo haces, cada rama se convierte en una **condición booleana independiente** que se evalúa en orden secuencial.

=== "Java (Cadena if - else if)"
    ```java
    String name = "Pedro";
    int score = 85;

    String description;
    if ("Admin".equals(name)) {
        description = "El usuario es un administrador.";
    } else if (score < 50) {
        description = "Necesita mejorar.";
    } else if (score >= 95) {
        description = "¡Excelente trabajo!";
    } else if (name != null && name.startsWith("P") && score > 80) {
        description = "Usuario destacado del grupo P.";
    } else {
        description = "Usuario estándar.";
    }

    System.out.println(description); // "Usuario destacado del grupo P."
    ```

=== "Kotlin (when sin argumento)"
    ```kotlin
    val name = "Pedro"
    val score = 85

    val description = when {
        name == "Admin" -> "El usuario es un administrador."
        score < 50 -> "Necesita mejorar."
        score >= 95 -> "¡Excelente trabajo!"
        name.startsWith("P") && score > 80 -> "Usuario destacado del grupo P."
        else -> "Usuario estándar."
    }

    println(description) // "Usuario destacado del grupo P."
    ```

Como puedes comprobar, cada rama es una expresión booleana arbitraria. Se ejecuta y retorna la primera cuya condición sea `true`, ofreciendo una alternativa mucho más limpia y compacta que encadenar múltiples `else if`.

### 4. `when` para Comprobar Tipos (con Smart Casting)

Este es uno de los usos más idiomáticos y potentes en Kotlin, especialmente para manejar polimorfismo y datos heterogéneos sin el molesto e inseguro casteo manual de Java.

#### A. Con Tipos Genéricos (`Object` en Java vs. `Any` en Kotlin)

El operador **`is`** comprueba el tipo en tiempo de ejecución. Al coincidir con la rama, el compilador realiza **Smart Casting** inmediato, permitiendo acceder a los métodos del tipo sin ninguna conversión explícita:

=== "Java (instanceof + casteo manual)"
    ```java
    public void processObject(Object obj) {
        if (obj instanceof String) {
            // En Java tradicional es obligatorio hacer un cast manual explícito:
            String str = (String) obj;
            System.out.println("Es un String con longitud " + str.length());
        } else if (obj instanceof Integer) {
            Integer num = (Integer) obj;
            System.out.println("Es un Entero con valor " + (num + 10));
        } else if (obj instanceof Boolean) {
            Boolean bool = (Boolean) obj;
            System.out.println("Es un Booleano invertido: " + !bool);
        } else {
            System.out.println("Es un tipo desconocido.");
        }
    }
    ```

=== "Kotlin (is + Smart Casting)"
    ```kotlin
    fun processObject(obj: Any) { // 'Any' es la raíz de todos los tipos en Kotlin (análogo a Object)
        when (obj) {
            is String -> {
                // Smart Casting: El compilador sabe que 'obj' es String aquí.
                // Accedes a propiedades y métodos de String directamente sin castear:
                println("Es un String con longitud ${obj.length}")
            }
            is Int -> {
                // Smart Casting: 'obj' se trata como Int
                println("Es un Entero con valor ${obj + 10}")
            }
            is Boolean -> {
                println("Es un Booleano invertido: ${!obj}")
            }
            else -> {
                println("Es un tipo desconocido.")
            }
        }
    }

    processObject("Hola Kotlin") // "Es un String con longitud 11"
    processObject(25)            // "Es un Entero con valor 35"
    ```

#### B. Con Jerarquías de Clases y Polimorfismo

El verdadero valor del Smart Casting se aprecia al trabajar con clases y herencia en POO. Observa la diferencia entre el código verboso de Java y la concisión de Kotlin:

=== "Java (Polimorfismo con casteo manual)"
    ```java
    public class Personaje {
        private final String nombre;
        public Personaje(String nombre) { this.nombre = nombre; }
        public String getNombre() { return nombre; }
    }

    public class Guerrero extends Personaje {
        private final int furia;
        public Guerrero(String nombre, int furia) {
            super(nombre);
            this.furia = furia;
        }
        public int getFuria() { return furia; }
    }

    public class Mago extends Personaje {
        private final int mana;
        public Mago(String nombre, int mana) {
            super(nombre);
            this.mana = mana;
        }
        public int getMana() { return mana; }
    }

    public class Arquero extends Personaje {
        private final int flechas;
        public Arquero(String nombre, int flechas) {
            super(nombre);
            this.flechas = flechas;
        }
        public int getFlechas() { return flechas; }
    }

    public void ejecutarHabilidadEspecial(Personaje p) {
        if (p instanceof Guerrero) {
            Guerrero g = (Guerrero) p; // Casteo manual obligatorio
            System.out.println(g.getNombre() + " activa Torbellino consumiendo " + g.getFuria() + " de furia.");
        } else if (p instanceof Mago) {
            Mago m = (Mago) p;
            System.out.println(m.getNombre() + " lanza Bola de Fuego gastando " + m.getMana() + " de maná.");
        } else if (p instanceof Arquero) {
            Arquero a = (Arquero) p;
            System.out.println(a.getNombre() + " dispara Lluvia de Flechas (" + a.getFlechas() + " restantes).");
        } else {
            System.out.println(p.getNombre() + " no tiene habilidades especiales.");
        }
    }
    ```

=== "Kotlin (Polimorfismo con Smart Cast)"
    ```kotlin
    open class Personaje(val nombre: String)
    class Guerrero(nombre: String, val furia: Int) : Personaje(nombre)
    class Mago(nombre: String, val mana: Int) : Personaje(nombre)
    class Arquero(nombre: String, val flechas: Int) : Personaje(nombre)

    fun ejecutarHabilidadEspecial(p: Personaje) {
        when (p) {
            is Guerrero -> println("${p.nombre} activa Torbellino consumiendo ${p.furia} de furia.")
            is Mago -> println("${p.nombre} lanza Bola de Fuego gastando ${p.mana} de maná.")
            is Arquero -> println("${p.nombre} dispara Lluvia de Flechas (${p.flechas} restantes).")
            else -> println("${p.nombre} no tiene habilidades especiales.")
        }
    }
    ```

!!! info "De Jerarquías Abiertas a Jerarquías Cerradas (`sealed`)"
    En el ejemplo anterior, como `Personaje` es una clase abierta ordinaria (`open`), el compilador nos exige incluir la rama `else` porque cualquier archivo del proyecto podría crear una nueva subclase `class Ladron : Personaje(...)`.
    
    Para evitar la necesidad de la rama `else` y lograr que el compilador verifique que cubrimos todas las variantes posibles en tiempo de compilación, Kotlin proporciona las **[Clases e Interfaces Selladas (Sealed Types)](./26-sealed-classes.md)**.

### 5. `when` para Comprobar Rangos y Colecciones

Puedes usar el operador **`in`** (y su inverso **`!in`**) para verificar de forma instantánea si un valor se encuentra dentro de un rango numérico o dentro de una colección.

=== "Java (Operadores relacionales y .contains)"
    ```java
    import java.util.Arrays;
    import java.util.List;

    int temperature = 25;
    List<Integer> numbers = Arrays.asList(1, 3, 5, 7, 9);

    if (temperature >= -10 && temperature <= 10) {
        System.out.println("Hace frío.");
    } else if (temperature >= 11 && temperature <= 22) {
        System.out.println("Está templado.");
    } else if (numbers.contains(temperature)) {
        System.out.println("¡Es un número impar de un solo dígito!");
    } else if (temperature < 0 || temperature > 100) {
        System.out.println("Temperatura fuera del rango normal.");
    } else {
        System.out.println("Temperatura agradable.");
    }
    // Salida: "Temperatura agradable."
    ```

=== "Kotlin (Operadores in y rangos ..)"
    ```kotlin
    val temperature = 25
    val numbers = listOf(1, 3, 5, 7, 9)

    when (temperature) {
        in -10..10 -> println("Hace frío.")
        in 11..22 -> println("Está templado.")
        in numbers -> println("¡Es un número impar de un solo dígito!")
        !in 0..100 -> println("Temperatura fuera del rango normal.")
        else -> println("Temperatura agradable.")
    }
    // Salida: "Temperatura agradable."
    ```

### Tabla Comparativa: `when` (Kotlin) vs. `switch` (Java)

| Característica | `switch` (Java) | `when` (Kotlin) | Ventaja de Kotlin |
| :--- | :--- | :--- | :--- |
| **Sintaxis básica** | `case X: ...; break;` | `X -> ...` | Más concisa y segura (sin `break;`). |
| **Valor por defecto** | `default:` | `else ->` | Nombres más intuitivos y uniformes. |
| **¿Puede ser una expresión?** | No tradicionalmente | **Sí** | Permite código funcional y elimina variables intermedias mutables. |
| **Exhaustividad** | No forzada por compilador | **Sí** (al usarse como expresión) | Código inmune a casos no contemplados. |
| **Tipos de condición** | Constantes (`int`, `String`, `enum`) | **Cualquier objeto, expresión o función** | Inmensamente más flexible. |
| **Combinar casos** | Sí (apilando `case` sin `break`) | **Sí** (usando comas `,`) | Más explícito y limpio. |
| **Uso sin argumento** | No es posible | **Sí** (`when { ... }`) | Sustituye cadenas de `if-else if` complejas. |
| **Comprobar tipos** | No directamente (`instanceof` + cast) | **Sí** (con `is` y Smart Casting) | Código sin boilerplate para polimorfismo. |
| **Comprobar rangos** | No directamente (`>=` y `<=`) | **Sí** (con `in X..Y`) | Sintaxis matemática limpia y declarativa. |

En resumen, `when` en Kotlin comienza como un simple `switch` pero se expande para convertirse en una de las herramientas de control de flujo más versátiles y seguras que existen en el ecosistema de desarrollo móvil y multiplataforma.
